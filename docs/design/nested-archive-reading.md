# 嵌套归档读取（#77）

Web 与 FUSE 应使用同一条成员读取链。当前已经具备外层 7z 的一级内包展开；任意 ZIP/7z/RAR 组合和更深层路径仍在 #77 中实施，不能仅凭页面显示链接判定支持。

## 按需读取的合同

`nestedMemberReader` 只缓存请求触及的 1 MiB 解压块。读取靠后的块可能需要先解码压缩前缀，但跳过的前缀不写入成员块缓存。相邻请求复用当前解码位置，向后未命中或闲置 30 秒后重新开流。完整磁盘命中直接读取，不占用解码额度，也不等待同一 reader 的活动解码。

`openArchiveMemberStream` 返回可提前关闭的成员流。7z 使用自有 group decoder；RAR 固实成员关闭 session，不能调用会解完整个剩余成员的 `SolidMember.Close`。普通 ZIP 暂时使用现有索引绑定的 `zip.File`；加密 ZIP 的通用输入适配尚未接入此接口，原有顶层加密 ZIP 路径保持不变。

最终块必须读到明确 EOF，才能发布该块。成员流保留终止错误，防止 `io.CopyN` 恰好读满长度时吞掉校验错误。部分块不代表整个成员已经通过 CRC 或认证校验，使用独立的 `nested-range-v3` 身份，不与完整验证缓存混用。7z 库未暴露 CRC 是否存在，沿用已有固实读取的零值兼容规则；仍检查长度和所有非零 CRC。

## 取消与递归额度

进入同步解码操作时，在创建缓存填充任务、锁定 reader 之前取得一次额度。递归祖先读取借用同一额度，最外层返回后失效；不能把这个额度交给后台异步生产者。这一顺序避免单额度下的递归死锁，以及持有子层额度却等待父层填充取得额度的循环等待。

每次 `ReadAtContext` 绑定当前请求，结束后解绑。保留的 decoder 下一次使用新请求的上下文，不能继续使用已经取消的第一次请求。请求取消只终止本次工作，不永久关闭 reader；挂载上下文取消也会中止活动读取。祖先 adapter 必须显式调用 `ReadAtContext`，裸 `ReadAt` 仅使用 reader 的挂载生命周期，不携带调用方的递归额度。

## 后续接入边界

- 用包含输入、格式、索引、完整祖先身份、深度和资源所有权的内部归档视图承载每层内容。
- 路径逐组件解析，目录只推进路径，显式进入归档成员才展开；保持 READDIRPLUS 不打开内包。
- 分卷从当前父索引的同目录查找，校验连续编号与总大小。
- Web/FUSE 的叶成员也复用按需 reader，移除 FUSE 小范围读取前的整成员提取。
- 通用化 ZIP 的输入、局部头与解密流后再接入格式组合；持久 reader 的输入不能保留第一次请求上下文。

最终验收包括真实 `7z → 7z → RAR → 视频`、Web/FUSE 字节一致、小于内包大小的缓存、单解码额度、取消后重试和长 TTL 下先枚举再进入的 FUSE 行为。目前基础测试通过不等于这些端到端条件已全部完成。
