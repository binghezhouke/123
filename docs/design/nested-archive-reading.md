# 嵌套归档读取（#77）

Web 与 FUSE 使用同一套归档视图和成员读取逻辑，支持 ZIP、7z、RAR 的内外层组合以及连续嵌套。云端归档为第 0 层，默认最多再进入 8 层；普通文件夹不计入深度。顶层与内层均支持 `.7z.001`、`.zip.001` 字节分卷和 `.z01 + .zip` 多磁盘 ZIP，其他分卷继续作为原始文件显示。

## 不可变内容约定

系统把所有内外层归档视为不可变内容。云端归档由账号范围内稳定的文件 ID 标识，已有版本和大小字段继续参与身份以兼容现有缓存；即使 API 未提供版本，也可持久复用归档索引。签名直链更换不表示归档内容变化。内层身份由完整祖先链、成员元数据和有效密码派生，分卷身份包含所有卷的有序文件 ID。

归档来源显式采用不可变读取策略。恢复来源不要求 API 版本、HTTP 验证器或未过期的直链；已有来源描述符保留原缓存命名空间，无可复用描述符时使用稳定的归档范围身份。缓存命中不先获取 URL 或探测字节零，只有实际缺失的范围才联网。旧 HTTP 验证器可参与缓存键，但不再作为不可变归档的条件请求头；响应范围、总大小、编码与长度校验仍保留。普通文件继续使用原来的验证器与来源 TTL 规则。

Web 归档入口和递归密码发现优先使用有效目录快照中的文件信息；缺失或过期时再查询 Detail。密码侧车仍可变化，仍按密码发现规则读取，不因归档内容不可变而持久保存密码。首次打开加密归档仍可能等待密码请求。

目录内容、文件名称、分卷成员集合和密码侧车可以刷新。用新文件 ID 替换某一卷后，新请求使用新集合的索引和缓存；已打开的目录和句柄继续使用原来的固定集合，不能把旧索引与新卷拼在一起。正常归档沿用既有缓存键；新增 ZIP 分卷使用独立命名空间。缓存仍受容量淘汰约束，不要求反复下载归档来证明内容未变。

## 视图与显式进入

`nestedArchive` 保存本层输入、格式、索引、完整祖先身份、有效密码身份和资源引用。`resolveArchivePath` 逐组件解析：普通目录只推进路径，显式进入归档成员才调用 `enterNestedArchive`。读取模式下最后一个归档成员保持原始字节；目录模式下进入其内容。同名普通目录及不同层的同名归档均保留，不折叠、不靠名字隐藏。

FUSE 的 `Node.Lookup` 才展开归档成员。目录枚举与诊断只查元数据，READDIRPLUS 对未展开成员返回 EAGAIN，让内核保留名称而不缓存错误的文件 inode。子视图和打开的叶句柄各自保留祖先引用，目录请求结束不会关闭仍在使用的输入；句柄关闭和取消分别处理。

ZIP Store 和经 sevenzip fork 确认的 7z Copy 输入可以直接映射到有界区间，避免读取无关前缀。独立成员采用严格的 AES7z→Copy 编码链时，使用库提供的按区间解密接口；`Stored` 仍只表示没有加密的 Copy。压缩、过滤、其他加密组合和固实流内的成员继续走原解码器，不能仅根据压缩前后大小相等做判断。

AES→Copy 快速路径要求单 packed input、已验证的 coder 绑定、相同的两级输出长度，以及按 16 字节补齐的密文长度。成员须覆盖整条输出流；重新解析得到的成员身份与持久索引一致后才使用。读取时只取目标区间覆盖的 AES 块，非首块额外取前一个密文块作为 CBC IV。尾部只按声明的明文长度裁剪，不按 PKCS#7 去除填充。源端仍按远端缓存窗口读取，因此下载量可能大于实际索引字节数。

随机解密对象只保存已验证的布局及自己持有的密钥材料，每次读取注入当前请求的来源；关闭时释放自己的状态，不清除库中共享的 KDF 缓存。它与普通直接映射一样保留叶成员完整连续读取的 CRC 校验，但局部读取不代表完整成员已经校验。只有明确不支持的布局才回退，损坏的布局和源读取错误直接返回。

RAR Store 快速路径由 rardecode 重新解析成员头确认：独立、完整单卷、非固实、已知长度、未加密、没有未支持的扩展哈希，且压缩后大小等于原始大小。库返回不持有来源、密码或请求上下文的范围对象，每次读取注入当前祖先输入；对象关闭后拒绝新读取，在途请求仍可完成。范围对象保留原生校验信息，单次完整读取或从零开始的连续读取才校验；乱序、重叠或局部读取不会触发额外前缀扫描，也不宣称完整校验。压缩、加密、固实、分卷与未支持布局回退到成员解码器。

## 按需解码与缓存

`nestedMemberReader` 只缓存请求触及的解压块，通常每块 1 MiB。小缓存按照最大嵌套深度缩小块大小，最多使用一半容量预算覆盖同步祖先填充的预留，另一半留给原始远端 Range。块大小进入缓存身份，避免更换容量或深度后复用不兼容的块。缓存小于内包本身也可读取索引和小范围正文。

读取靠后的压缩块可能需要先解码前缀，但跳过的前缀不写入成员块缓存。相邻请求复用当前解码位置，向后未命中或闲置 30 秒后重新开流。完整磁盘命中不占解码额度，不等待活动解码。完整文件缓存、原始远端区间和按需解压块不混用。

`openArchiveMemberStream` 返回可提前关闭的成员流。7z 使用自有 group decoder；RAR 固实成员直接关闭 session，不调用会解完整个剩余成员的 `SolidMember.Close`。ZIP 的局部头、Store/Deflate、ZipCrypto 和 AES 使用通用输入，顶层与嵌套共用校验和解密实现。

解码流的最终块必须确认 EOF、长度与可用的 CRC/认证后才发布，终止错误不可被 `CopyN` 吞掉。部分块不代表完整成员已通过认证。7z 库尚未暴露 CRC 是否存在，沿用非零 CRC 校验规则。直接映射的叶成员保持随机读能力，只在读取覆盖完整连续内容时校验 CRC，不为了部分 Range 额外扫描全文件。

缓存身份包含云端内容版本、格式、祖先链、原始成员名、序号、大小、CRC、有效密码和分卷顺序，避免不同内包、同名成员或不同密码互相命中。

完整内层索引通过现有归档索引缓存持久复用，不设置内容过期时间，仍受容量和索引保留预算约束。缓存只存成员元数据；每次进入创建独立视图，ZIP 成员重新绑定当前祖先输入，不保存读取器、请求上下文、密码或直链。重新启动后可恢复同一份索引，未完成或失败的索引不会作为完整结果发布。恢复后仍检查本层和祖先累计元数据预算。

清晰头部先按无密码身份查找索引，只有加密头部拒绝解析时才发现当前密码，再用其身份查询缓存；成员正文加密仍在读取时发现密码。普通内层 ZIP 为判断是否多磁盘分卷仍会读取有限尾部，复用索引不等于每次完全零源读取。RAR 索引显式记录正文加密状态，缺少该字段的旧 RAR 索引会重建；请求取消不会删除有效的索引缓存。

## ZIP 分卷与索引

`.zip.001` 作为字节分卷入口，要求同目录连续的规范编号；密码侧车使用 `名称.zip.pwd`。真正的多磁盘 ZIP 从最后的 `.zip` 进入，先读取其有限尾部，再根据 EOCD 声明寻找 `.z01`、`.z02` 等前序卷。普通 ZIP 即使旁边存在同名前缀的 `.zNN`，也不自动合并。缺卷、歧义、无效大小、越界磁盘地址和超过 1000 卷的集合会明确失败。

`preparedArchiveInput` 固定原始输入、总大小、卷顺序和缓存身份，索引及成员打开共用这一份输入。前序卷直到真正读取时才初始化来源或祖先解码器。只读取尾部和中央目录元数据，不生成完整合并文件。

多磁盘 ZIP 的中央目录使用卷内偏移。索引适配器把它们转换成全局偏移，并在虚拟尾部追加有界的单磁盘目录与 ZIP64 结束记录，复用现有 ZIP 名称、权限和加密解析。原始成员字节完全不变；成员读取始终使用原始总大小。支持中央目录和成员跨卷、ZIP64 条件扩展字段，以及全局偏移超过 4 GiB 时的 ZIP64 提升。

中央目录编码和转换后的元数据均受预算限制。加密中央目录、需要猜测偏移的特殊自解压分卷，以及无法从末卷尾部识别结束记录的布局暂不支持。已有压缩祖先读取后段时仍可能需要顺序解码前缀，分卷映射不能消除压缩格式本身的依赖。

## 取消、密码与并发额度

密码发现可能加载目录元数据，因此必须先于解码额度获取；索引缺密码时先释放额度，再发现密码和重试。有效密码沿用现有侧车与递归共享密码规则，只在内存短暂解密，不进入日志或缓存身份明文。

每层仍独立选择专属或最近的共享密码侧车，但侧车内容按文件 ID、版本、大小、所在目录和快照代次共享加密内存缓存。同一侧车用于多个归档或嵌套层时合并读取；目录刷新后重新读取，即使侧车没有版本字段。进程重启仍从网盘读取密码，不持久保存密码内容。

同步解码在创建缓存填充任务、锁定 reader 之前取得一次额度。递归祖先读取借用同一额度，最外层返回后失效；不能把它交给后台生产者。这样单额度下也不会发生子层占额度却等待父层填充的死锁。

每次 `ReadAtContext` 绑定当前请求，结束后解绑。保留的 decoder 下次使用新请求的上下文，不继续使用已经取消的第一次请求。FUSE 每次 Read 传入独立请求，Web 句柄沿用该 HTTP 请求；请求取消终止本次工作，不永久关闭 reader。挂载取消会中止活动读取。

## 验收边界

自动化覆盖九种格式组合、三层路径、内层分卷、同名隔离、密码继承、单额度、小于成员大小的缓存、CRC 错误、取消后重试和真实 FUSE 长 TTL 下先枚举再进入。真实网盘验收使用 `mount123/tools/live_acceptance.py`，记录目录数量、分页完整性、Web/FUSE Range 字节一致性、耗时与缓存统计。暖缓存结果不能称为冷读延迟；固实压缩到目标偏移之前所需的解码量仍由格式决定。
