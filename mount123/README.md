# mount123：Linux 只读网盘挂载

独立 Go 命令，通过 123 开放平台 API 获取目录和下载直链，不经过 WebDAV，也不依赖 Python 网页服务启动。使用 [go-fuse v2](https://github.com/hanwen/go-fuse) 与 Go 标准库 [archive/zip](https://pkg.go.dev/archive/zip)。选型对比见[调研文档](../docs/research/go-readonly-mount.md)。

## 构建和运行

需要 Linux、Go 1.23 或更新版本、FUSE（例如 Debian/Ubuntu 的 `fuse3`），以及可访问的 `/dev/fuse`。使用普通用户运行。容器需要额外开放 FUSE 设备与挂载权限。

```bash
cd mount123
go build -o mount123 ./cmd/mount123
mkdir -p "$HOME/mnt/123"
./mount123 \
  -config ../config.json \
  -mountpoint "$HOME/mnt/123" \
  -cache-dir "$HOME/.cache/mount123" \
  -cache-gib 20 \
  -metadata-mib 64 \
  -directory-ttl 30s \
  -source-ttl 30s \
  -root-id 0
```

`config.json` 沿用网页服务的 `CLIENT_ID`、`CLIENT_SECRET` 字段。也可通过环境变量 `PAN123_ACCESS_TOKEN` 提供现成令牌；仅提供令牌时不强制要求配置文件存在，令牌过期后需要自行更换。应用凭据方式会自动申请、缓存和刷新令牌。缓存按应用 ID 与 API 地址隔离，不复用旧 Python 客户端未标记账户的令牌文件。

程序前台运行，Ctrl+C / SIGTERM 会卸载；也可以从另一终端执行：

```bash
fusermount3 -u "$HOME/mnt/123"
```

挂载点必须已存在且为空。缓存必须放在挂载点之外；同一缓存目录仅允许一个挂载进程使用。默认只对当前用户开放挂载，不开启 `allow_other`。

挂载会在私有缓存目录创建权限为 `0600` 的 `control.sock`，卸载时删除。`status` 和 `wait-index` 通过该本地 Unix socket 查询运行中挂载的真实索引状态；socket 只接受当前用户连接，不返回下载 URL 或密码。默认 socket 路径是 `os.UserCacheDir()/mount123/control.sock`，挂载使用自定义缓存目录时，命令也要传相应的 `-control-socket`。

```bash
./mount123 status [-control-socket PATH] <挂载内归档路径>
./mount123 wait-index [-control-socket PATH] [-timeout 10m] <挂载内归档路径>
```

路径可写相对挂载根的路径，也可写挂载点下的绝对路径。Go flag 规则要求选项写在路径之前。`status` 会在需要时启动索引并立即报告 `queued`、`scanning`、`complete` 或 `failed`；`wait-index` 持续等待直到完成，按 Ctrl+C 可取消。输出包含已发现成员数、扫描高水位和归档大小；无法精确统计时下载字节数显示为 `unknown`。退出码：`0` 表示查询成功或索引完成，`1` 表示用法、连接或路径错误，`2` 表示索引失败，`3` 表示等待超时，`130` 表示用户取消。

## 文件如何呈现

```text
~/mnt/123/
├── 普通目录/
│   └── 视频.mp4
└── 相册.zip/             # 保留 ZIP 文件名，但作为目录进入
    └── images/
        └── 001.jpg
```

`-zip-dirs=false` 可关闭映射，把所有支持的压缩包当作普通文件读取。目录列表完整翻页，云端单项查找、密码侧车发现和分卷发现按目录 ID 共享不可变快照，默认缓存 30 秒，可用 `-directory-ttl` 调整；压缩包内单项查找只构造目标成员，Readdir 仍列出完整目录；FUSE 属性与目录项缓存 1 秒。挂载通过内核 `ro` 选项拒绝写入、创建、重命名、删除，节点也拒绝写方式打开及属性修改。挂载过程只读取网盘；只有显式执行 `unlock` 子命令时才上传同级密码文件。

非零 `-root-id` 会在挂载前通过 Detail 验证为未删除目录；根 ID `0` 表示合成的“我的文件”根并跳过 Detail。FUSE `mtime`/`ctime` 使用云端更新时间；更新时间缺失时回退到创建时间。API 的无时区日期按中国标准时间 UTC+8 解释。

## 读取和缓存

- 普通文件：1 MiB 分块读取，使用 API 下载直链的 HTTP Range，按需缓存。按文件 ID、版本和大小复用远端读取器，跨次打开在 `-source-ttl`（默认 30 秒）内共享直链和实体验证结果；读取器内部的直链过期或返回 401/403/404/410 时重新获取一次。
- ZIP 索引：读取中央目录，进入目录时不预先下载整个 ZIP；按远端内容版本共享解析后的索引，节点回收不会直接丢失共享缓存；打开成员时才读取该成员的本地头部。完整中央目录 DTO 按版本持久化，按内容版本和 LRU 复用，不使用 30 秒失效时间。
- Store 成员：直接定位 ZIP 数据区，支持随机读取，无需完整解压。
- Deflate 成员：第一次打开时流式解压到磁盘，并完成 CRC 校验后返回文件句柄；后续在缓存中随机读取。大成员首次打开会等待，不是边解压边返回文件内容。
- 已完整物化并校验的 ZIP Deflate/加密成员及 7z/RAR 成员默认允许 Linux 内核页缓存；每次新 Open 仍先检查当前密码身份和磁盘缓存键。`-archive-page-cache=false` 可关闭该页缓存。ZIP Store 成员和普通云端文件仍按需 Range 读取，不启用内核页缓存。
- 缓存默认 20 GiB，可用 `-cache-gib` 调整；包含已下载块、完整解压成员和正在写入的预留空间。LRU 淘汰未使用内容，打开的解压文件保持占用直到关闭。单个成员超出预算或所有可用空间被占用时返回空间不足。解压时还需要留出读取压缩块的余量。
- 缓存文件原子发布、私有权限，异常退出的临时文件下次启动清理；按云端版本和 HTTP 验证器区分内容。没有可用验证器时不跨读取器复用缓存。缓存是工作缓存而非离线副本，需要联网解析直链和验证源文件。
- 缓存根目录保存一个权限为 `0600` 的随机 HMAC 密钥，用于生成稳定且按 API 身份隔离的密码指纹；磁盘缓存不保存密码、凭据或下载 URL。进程内密码加密仍使用每次挂载随机生成的密钥。

目录快照、归档索引和远端读取器共用独立的内存缓存，默认估算容量 64 MiB，可用 `-metadata-mib` 调整；按最近使用情况淘汰。它不属于磁盘 `-cache-gib` 配额，也不是整个进程 RSS 的硬上限：内核持有的活动节点、打开文件的描述符和构建期间的临时对象仍会占用内存。成功完成的 ZIP/7z/RAR 索引也会以版本化 DTO 保存在磁盘缓存内，计入 `-cache-gib` 字节预算；ZIP 保存本地文件头偏移及中央目录成员元数据，RAR 保存可重新验证的头部定位记录。索引文件不含读取器、密码、解密状态或下载 URL。异常退出、格式版本不兼容或身份不匹配时会重建索引。加载按键合并，同时最多构建 4 份元数据；单份快照超过预算会报错，可增加 `-metadata-mib`。

有效期到期后，在下一次访问时刷新，不后台轮询。父目录发现文件版本变化后，新路径使用新索引；已打开的旧目录或文件仍可保持旧快照。增大有效期会减少 API 请求，也会延迟外部修改的可见性。

普通文件时间默认来自目录 List 元数据，不额外查询每个文件；`Getattr` 使用 inode 持有的不可变快照。可启用 `-file-info`，让 Lookup 对活跃云端条目按需调用 Infos，最多每批 100 个 ID，并按元数据 TTL 缓存结果。它能发现已删除条目并刷新云端时间，但会增加 API 请求，因此大目录 `find`/遍历可能更慢；默认关闭。读取过程中若文件大小或版本与父目录快照不一致，Lookup 返回 `ESTALE`，等待目录快照 TTL 后重新查找。Infos 队列最多等待 400 个条目，批次受 5 ms 合并窗口和最多 4 个元数据构建并发限制；请求取消会退出等待，全部批次请求取消时也会取消 API 请求。遇到 429 最多重试 4 次；服务端要求等待超过 30 秒时返回错误。

普通读取、ZIP 索引构建和成员解压会传递每次操作的取消信号；取消一个请求不会取消其他打开句柄。并发请求共用的缓存填充如果由被取消的请求发起，仍存活的等待者可以重新发起填充。

## 支持边界

支持普通文件、单卷 ZIP（Store / Deflate，包括标准库支持的 ZIP64）以及采用 AES 或 ZipCrypto 加密成员的 ZIP。另支持 7z、7z 分卷（从 `.7z.001` 进入）、单卷 RAR，包括加密目录、加密成员和固实压缩。传统加密使用 [yeka/zip](https://github.com/yeka/zip) 的分块解密状态机，AES 使用 Go 标准密码库和 PBKDF2，支持 128/192/256 位、AE-1/AE-2。加密 ZIP 首次打开成员时会把明文流式解密到私有临时缓存，完整校验大小、CRC（适用时）和 AES 认证码后才发布缓存并返回文件句柄。ZIP 加密中央目录、ZIP 的其他压缩算法、分卷 ZIP、分卷 RAR、嵌套压缩包自动映射暂不支持。ZIP 内部的另一个 ZIP 作为普通成员文件读取。

7z 使用纯 Go 库 [bodgit/sevenzip](https://github.com/bodgit/sevenzip)，RAR 使用 [nwaples/rardecode](https://github.com/nwaples/rardecode)，运行时无需 `7z` / `unrar` 命令。7z/RAR 从同级 `文件名.7z.pwd` / `文件名.rar.pwd` 读取密码；7z 分卷共用 `文件名.7z.pwd`，要求所有卷在同一网盘目录、从 001 连续编号，最多 1000 卷。只有 `.7z.001` 映射为目录，后续卷保留为普通文件。分卷按需获取直链和读取，缓存键包含整组分卷版本。

7z/RAR 成员首次打开会完整解压至指定缓存目录，校验大小及校验和后才返回句柄；后续读取可复用缓存。固实包打开靠后的成员可能解压前序数据，所以首次打开可能较慢，不能保证即时播放。索引解析默认有 64 MiB 读取预算（提高 `-archive-max-entries` 时按每条 512 字节增加，取两者较大值），RAR 解码字典上限为 64 MiB，索引构建和成员解压共用最多 4 个并发槽；超过预算返回错误。成员解压空间计入 `-cache-gib`，空间不足返回 `ENOSPC`。所有格式都拒绝链接、特殊文件和不安全路径。密码缺失或错误时，加密目录/成员返回 `EACCES`；终端不会自动弹出密码输入。网页生成的 `.pwd` 可直接使用。密码及不存在密码文件的结果都按目录 TTL 缓存，修改后在刷新周期到期触发后台刷新，完成后后续访问生效。

加密 ZIP 需要一个与压缩包同目录、命名为 `<archive name>.pwd` 的云端普通文件作为密码侧车。中央目录未加密时，仍可进入 ZIP 目录并列出成员；读取成员需要正确密码。缺少侧车或密码错误时，成员打开返回 `EACCES`，不会在挂载中提示输入。设置 `-zip-dirs=false` 后，所有格式均作为原始压缩文件读取。侧车密码按目录快照 TTL（默认 30 秒）自动读取；自动读取的密码只保存在进程内存。用户通过普通文件方式打开 `.pwd` 侧车时，它会像其他云端文件一样进入磁盘缓存。侧车本身按用户要求以明文保存在云盘中。

每个加密 ZIP 的最小加密成员会在首次验证密码时完整解密并校验；挂载时首次打开具体成员，也会先完整解密到私有磁盘缓存再返回文件句柄。一个压缩包包含多个加密成员时，最小成员验证成功不保证其他成员也使用相同密码；其他成员若密码不同会返回 `EACCES`。加密中央目录尚不支持。

`unlock` 子命令目前用于 ZIP，可验证密码并创建或替换侧车；7z/RAR 请先在网页验证并生成 `.pwd`。密码不会作为命令行参数传递：默认在终端隐藏输入，也可从标准输入读取。该命令会先完整验证一个最小的加密成员，只有验证成功后才上传密码。为了避免密码写入 shell 历史，标准输入示例使用权限受限的文件作为密码来源：

```bash
./mount123 unlock -file-id 12345 -config ../config.json
./mount123 unlock -file-id 12345 -password-stdin -config ../config.json < /path/to/password.txt
```

`-cache-dir` 可指定现有私有缓存根目录；命令复用其中的 `token.json`，并在根目录下建立临时私有缓存目录，磁盘缓存上限为 256 MiB，退出时删除。无有效侧车或密码错误时挂载不会弹出输入提示。

要求下载源返回正确的 HTTP 206 和 Content-Range；不支持 Range 时明确失败，不会悄悄下载整个大文件。读取期间实体验证器变化会报错，避免拼接不同版本。源站完全不提供验证器时无法保证读取期间源文件不变。Store 随机读取不做全成员 CRC 扫描；Deflate 完整解压会校验 CRC。

ZIP 名称优先使用 UTF-8 标记或 CRC 校验通过的 Unicode Path 扩展字段；未标记且非 UTF-8 的旧名称尝试 GB18030，再回退 CP437。旧编码没有可靠标记时仍存在识别歧义；拒绝路径穿越、符号链接、重名和文件/目录冲突。ZIP 最多 100,000 条中央目录记录，命令行挂载展开后的文件和隐式目录合计默认最多 200,000 个节点，路径深度最多 128，累计名称预算 16 MiB，中央目录编码大小上限 64 MiB。解析前预检真实记录数，预检及标准库解析每遍另留有限尾部记录读取余量；不对成员文件设置额外的 32 MiB 限制。索引 DTO 与缓存的 Range 数据计入磁盘缓存预算；内存索引副本、令牌文件及文件系统元数据开销不计入 `-cache-gib`。

## 验证

```bash
go test -race ./...
go vet ./...
# 真实 FUSE 挂载，使用本地模拟 API 数据，不访问个人网盘：
MOUNT123_FUSE_TEST=1 go test -race -run TestActualFUSEMount -v ./internal/mountfs
```

测试覆盖 API 授权/分页、缓存预算与并发、HTTP Range 验证、普通文件和 ZIP 随机读取，以及实际挂载后的写入/创建/删除/重命名拒绝。真实网盘验收结果见[验收记录](live-validation.md)。

下载直链按获取时间缓存 **6 天**，为实测约 7 天的签名有效期保留一天余量。直链缓存在挂载进程内独立保存，最多 4096 条，不随目录或远端读取器 TTL 失效；重建读取器沿用原到期时间，不重新累计 6 天。并发获取合并，链接提前返回 401/403/404/410 时重新获取并重试一次。进程重启后按需重新获取直链，不把签名链接写入磁盘。

## 图片启发式预取

默认启用相邻图片预取，参数 `-prefetch-files=9 -prefetch-workers=2 -prefetch-mib=256`。实际读到图片数据后，同目录按自然文件名排序预测下一张，首次取后面 2 张，连续同向浏览扩大到 4、9 张；反向时取前面的图片，跳跃时缩小窗口。每次继续浏览都会推进预取窗口。普通目录和 ZIP 均可预取；7z/RAR 每轮最多预取 1 张以控制固实解压成本。

只有实际读取图片才触发，`ls`、`stat`、仅打开不读取及普通 `find` 不触发；缩略图程序实际读图可能触发，无法确定用户的界面排序。启用预取时图片保持 `DIRECT_IO`，让每次实际读取都进入 FUSE 并推进正向或反向预取窗口；关闭预取后，已完整物化的归档图片可使用 `-archive-page-cache` 的内核页缓存。其他已物化归档成员也可使用该页缓存；`-archive-page-cache=false` 可统一关闭。新的前台打开若命中正在预取的目标则复用填充，否则取消旧预取，后台任务最多运行 30 秒，不递归触发更多预取。256 MiB 是每轮目标图片总大小预算，超预算图片只跳过预取，前台读取不受此限制；固实包的前序读取量可能更大。复用现有磁盘缓存与并发填充合并，预取失败不影响正常读取。`-prefetch-files=0` 可完全关闭。该功能是跨图片预测，与单文件字节级自适应预读分别控制。

详细设计与参考资料见 [挂载图片预取设计](../docs/design/mount-prefetch.md)。

## 普通文件顺序预读

普通云文件和 ZIP Store 成员只在实际读取后触发字节级预读，连续读取时窗口从 1 MiB 扩大到 4 MiB、最高 16 MiB；跳读会取消旧窗口并回到 1 MiB。每个打开句柄最多两个后台 Range 请求，窗口总量受缓存预算限制，关闭句柄会取消并等待后台读取。ZIP Store 预读严格限制在成员数据范围内。`-read-ahead-mib=0` 可关闭，默认上限为 16 MiB；打开、stat 和列目录不会触发。

磁盘数据缓存默认使用 `-cache-durability=durable`，写入后同步到磁盘并跨重启复用。可选 `-cache-durability=ephemeral` 使用每个进程独立的临时子目录，省去文件同步并在关闭时删除；异常退出遗留的目录会在下一次启动时清理，不会复用。认证 token 缓存始终保留在所选缓存根目录的 `token.json`，因此切换到 ephemeral 或重启不会丢失登录 token。

## 大型 RAR 首次列目录

RAR 的文件头分散在成员数据之间，首次列目录必须逐个扫描，不能像 ZIP 一样只读尾部中央目录。大量小文件的 RAR 即使不解压内容，也可能需要很长时间。扫描使用 512 字节解析缓冲；起初以 64 KiB 小块读取并复用已有的 1 MiB 数据块。连续三次读取位置相距不超过 1 MiB 时，按 1→4→16 MiB 扩大连续读取窗口，每个窗口只发一个 HTTP Range 请求，并缓存至磁盘与当前扫描的内存。遇到超过 1 MiB 的跳跃时停止扩大窗口，已在窗口内的数据仍复用，后续按稀疏模式重新判断。密集小文件包因此会多下载一部分正文，以减少串行请求次数；通过基于 `rardecode` 的逐条文件头回调跳过成员数据，固实包列目录也不解压前序成员。成功跳转后的 CDN 地址在当前读取器内复用。

7z/RAR 索引扫描由后台任务执行，同一索引的请求合并。等待完整索引的操作超过 5 秒返回 `EAGAIN`（终端通常显示 `Resource temporarily unavailable`），后台继续构建；RAR 的交互目录浏览使用下文的快照方式，无需等待完整索引；取消前台请求不会丢弃扫描进度。最多 4 个后台索引任务，每次最长 30 分钟，卸载会取消任务。日志每 30 秒记录 RAR 扫描位置：`offset` 是当前读取位置，`size` 是整个压缩包大小，单位均为字节。可用 `offset / size` 观察位置推进；两者都不表示累计下载量或解压量。根目录的 `cd` 不必等待列目录，普通 `ls` 使用下文的部分目录快照。

完成后的 7z/RAR 索引在当前进程中按内容版本和密码缓存，有效期 365 天，仍受内存 LRU 预算限制；成功完整索引同时写入磁盘缓存，重启后可直接恢复。大目录可提高 `-metadata-mib` 和 `-archive-max-entries`（默认 100000，最多 1000000），展开节点上限为条目上限的两倍。增加限制不会消除首次扫描所需的网络往返。

### RAR 渐进式目录

RAR 扫描发现成员后立即发布对应文件与隐式父目录。**每次打开目录取得当时已发现条目的固定快照**，普通 `ls` 排序并输出该快照后立即结束，不等待整个归档扫描；再次 `ls` 会看到新增项目。同一目录句柄中新增条目不会改变原快照，重置游标也保持一致。

已发现的目录可立即进入，已发现的文件可直接查询或打开。尚未扫描到的名字返回 `EAGAIN`，不提前报告 `ENOENT`，避免 Git 提示符等探测把终端拖住。如果尚未发现任何条目，最多等待第一批 1 秒，再返回 `EAGAIN`；该等待不包含首次 API/直链准备。扫描完成后，新的目录快照就是完整列表。

索引完成前，`ls`、`find` 等遍历看到的都是当时已发现的部分内容，不能据此判断全包文件数；这是为了快速交互浏览而采用的快照语义。无需专门使用 `ls -U`。7z 仍先解析其集中存储的头部索引，未承诺渐进解码其索引。

`third_party/rardecode` 保留 v2.2.1 的原始源码和许可证，只在 `walk.go` 中增加文件头遍历、位置记录和定点打开接口，以便不解压固实正文也能逐条发布文件头。具体改动见该目录的 `LOCAL_CHANGES.md`。

### 稳定索引身份

同一挂载账户内，ZIP/7z/RAR 索引以 File ID、API 内容版本和大小定位，再区分格式与密码。名字、父目录路径和临时下载 URL 都不作为索引身份；移动或同格式改名不重建索引，内容版本或密码变化则分别建索引。API 没有提供版本时使用 HTTP 验证器回退。分卷索引额外包含有序分卷 ID、版本和大小。索引缓存按账户和 API 地址隔离，并受磁盘字节预算与内存 LRU 约束。

带 API 内容版本的 7z/RAR 读取器至少复用 6 天（仍受内存 LRU 淘汰影响），避免每 30 秒重新探测同一归档。下载直链仍在到期或被拒绝时刷新；目录列表的 30 秒刷新周期不变。完整索引落盘后，重启时仍需联网探测源文件并校验当前身份，但不重新扫描归档头。

### RAR 成员首次读取与元数据刷新

RAR 索引同时保存成员头的位置。非固实成员首次打开时读取归档前导头、直接跳到目标头部，使用当前密码重新解析，然后仅解压该成员并校验；不再按成员序号从头遍历。定位记录不含密码、解密密钥或读取器。固实成员仍可能依赖前序解压，不能保证相同的首次读取速度。

已有云端目录列表、密码侧车信息（包括不存在侧车的结果）超过刷新周期后，当前操作先使用已有快照，后台合并刷新；最多 4 个刷新任务，45 秒超时。成功后后续访问使用新快照；刷新失败会移除旧快照，下次访问重新加载。首次缓存缺失仍需请求网盘。外部修改的可见时间因此包含后台刷新耗时，而不仅是默认 30 秒；已打开的旧文件快照不被替换。

### 前台任务优先

归档后台扫描、过期元数据刷新和图片预取标记为后台工作。构建/解压默认最多 4 个任务，其中最多 3 个后台任务；下载默认最多 8 个请求，其中最多 7 个后台请求。空闲槽优先交给等待中的前台任务，运行中的请求不会被强制中断。同一缓存填充仍共享结果，所以读取正在预取的目标可能需要等它完成。自定义构建容量为 1 时只有排队优先级，无法同时预留前台槽。限制控制并发，不承诺带宽配额。
