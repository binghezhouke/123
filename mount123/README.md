# mount123：Linux 只读网盘挂载

独立 Go 命令，通过 123 开放平台 API 获取目录和下载直链，不经过 WebDAV，也不依赖 Python 网页服务启动。使用 [go-fuse v2](https://github.com/hanwen/go-fuse) 与 Go 标准库 [archive/zip](https://pkg.go.dev/archive/zip)。选型对比见[调研文档](../docs/research/go-readonly-mount.md)。

## 构建和运行

需要 Linux、Go 1.26 或更新版本、FUSE（例如 Debian/Ubuntu 的 `fuse3`），以及可访问的 `/dev/fuse`。使用普通用户运行。容器需要额外开放 FUSE 设备与挂载权限。

```bash
cd mount123
go build -o mount123 ./cmd/mount123
mkdir -p "$HOME/mnt/123"
./mount123 \
  -config ../config.json \
  -mountpoint "$HOME/mnt/123" \
  -cache-dir "$HOME/.cache/mount123" \
  -cache-gib 50 \
  -cache-durability durable \
  -metadata-mib 64 \
  -directory-ttl 24h \
  -source-ttl 144h \
  -read-ahead-mib 16 \
  -download-requests 32 \
  -download-bytes-mib 128 \
  -download-foreground-reserve-mib 16 \
  -stream-members=true \
  -root-id 0
```

`config.json` 沿用网页服务的 `CLIENT_ID`、`CLIENT_SECRET` 字段。也可通过环境变量 `PAN123_ACCESS_TOKEN` 提供现成令牌；仅提供令牌时不强制要求配置文件存在，令牌过期后需要自行更换。应用凭据方式会自动申请、缓存和刷新令牌。缓存按应用 ID 与 API 地址隔离，不复用旧 Python 客户端未标记账户的令牌文件。

程序前台运行，Ctrl+C / SIGTERM 会卸载；也可以从另一终端执行：

```bash
fusermount3 -u "$HOME/mnt/123"
```

挂载点必须已存在且为空。缓存必须放在挂载点之外；同一缓存目录仅允许一个挂载进程使用。`-cache-dir` 默认是 `os.UserCacheDir()/mount123`，Linux 通常为 `$HOME/.cache/mount123`。默认只对当前用户开放挂载，不开启 `allow_other`。

挂载会在私有缓存目录创建权限为 `0600` 的 `control.sock`，卸载时删除。`status` 和 `wait-index` 通过该本地 Unix socket 查询运行中挂载的真实索引状态；socket 只接受当前用户连接，不返回下载 URL 或密码。默认 socket 路径是 `os.UserCacheDir()/mount123/control.sock`，挂载使用自定义缓存目录时，命令也要传相应的 `-control-socket`。

```bash
./mount123 status [-control-socket PATH] <挂载内归档路径>
./mount123 wait-index [-control-socket PATH] [-timeout 10m] <挂载内归档路径>
./mount123 io-stats [-control-socket PATH]
./mount123 io-stats [-control-socket PATH] -interval 30s -count 10
./mount123 refresh [-control-socket PATH] <挂载内云端目录路径>
./mount123 doctor [-control-socket PATH] [--retry] <挂载内路径>
```

`io-stats` 无需文件路径，返回当前挂载进程的 JSON 统计，包括前台读取等待、下载排队、HTTP 正文首字节与传输、缓存发布耗时和命中字节。未接入或尚无观测的指标显示 `unknown`/`null`。这些是进程累计数据；比较场景时记录前后快照，同时测量应用实际读取时间。 `stages` 新增目录、来源准备、直链、源探测、构建排队、索引、解压和打开耗时；阶段可重叠，不能相加。`cache.fill_cancelled` 与 `fill_errors` 区分主动取消和其他失败，`image_prefetch` 记录窗口复用等事件。可重复本地基线见 [I/O 诊断说明](../docs/netfs-io-baseline.md)。

默认每 30 秒将快照和区间分析追加到缓存根目录的 `io-stats.jsonl`，启动和退出也记录；单文件最多 8 MiB，保留一份 `.1`，权限为 `0600`。`-stats-interval=0` 可禁用。历史记录保留会话开始时间和实际 TTL/预取配置；进程重启后操作计数重新开始，已恢复的缓存占用仍可见。日志最多约 16 MiB，不计入 `-cache-gib` 的数据预算。

统计包括缓存容量/占用/被打开文件占用、各保留等级、淘汰量、近期淘汰后再次请求的次数、填充失败，以及前后台 Range 读取命中字节。`io-stats -interval 30s -count 10` 输出连续样本和区间差值；省略 `-count` 持续采样。分析会区分冷读、容量反复淘汰和未用完的连续预读，给出有依据的比较建议；样本不足时明确标记，不自动改变参数。计数边界及调优方法见 [缓存测量与调优](../docs/netfs-cache-tuning.md)。

`refresh` 强制重新获取指定云端目录的当前一层列表，成功后更新本地目录快照和内核目录项缓存；无需等待 24 小时 TTL。它不递归扫描，不清空文件内容缓存，也不重建 ZIP/7z/RAR/ISO 内部索引。网盘上新增、删除、改名或修改密码侧车后，对其所在云端目录执行刷新，再重新打开目录即可。已有目录句柄保持原来的冻结快照。普通 `ls` 或文件管理器 F5 不携带专用的强制刷新标记。

也可直接在挂载中的**云端目录**读取虚拟控制文件，无需知道 `mount123` 程序或控制 socket 的路径：

```bash
cat .mount123-refresh
# entries=260
```

每次只读打开触发一次刷新；成功后输出当前层条目数，失败通过文件打开错误报告，并保留旧列表。
控制文件不会上传网盘，也不会出现在目录列表中；查询它的属性、普通 `ls` 和 `find` 不触发刷新。
它仅用于云端目录，ZIP/7z/RAR/ISO 内不增加这个入口。云端若本身有同名文件或目录，会显示为带 `[id=...]` 的别名，仍可正常访问。
同一目录同时发起的控制文件/CLI/自动刷新合并处理，单次等待最多 25 秒；挂载继续使用内核 `ro` 选项。

实际打开加密 ZIP 成员时，如果当前快照找不到同级密码文件，会自动刷新父目录并重新查找一次。
这也适用于重挂载后恢复的旧目录快照。自动刷新按父目录冷却 30 秒（失败也冷却），普通列目录、索引扫描和后台预取不触发它。
已有但错误、空或重名的密码文件不会反复触发自动刷新；修正后可用 `cat .mount123-refresh` 或 `mount123 refresh` 立即刷新，手动操作不受自动冷却限制。
此自动补救仅覆盖 ZIP 缺失密码侧车；7z/RAR 仍可用同样的手动目录刷新入口。

`doctor` 返回路径诊断 JSON，包含当前阶段、状态、原因和建议操作。普通文件只读取少量样本；归档内部通过索引检查，不为诊断完整解压成员。`metadata_only` 表示正文未验证，嵌套归档中尚未检查的路径会明确报告。检查归档可能启动已有的后台索引任务。`--retry` 允许重试已失败且未在运行的索引任务，普通目录更新仍使用 `refresh`。诊断不输出下载 URL、凭证、密码或文件正文。

目录快照现已按账号和目录 ID 写入有容量限制的持久缓存，重启沿用原获取时间和 TTL。临时网络故障时先保留旧列表并退避刷新；权限、路径失效或无效数据分别处理。成功列表即使未能写入磁盘缓存也仍可在内存使用。`io-stats` 新增 `directory_cache` 和 `remote_recovery`，分别记录目录恢复/刷新及 Range 重试；这些也会进入周期日志与区间报告。行为与计数边界见 [故障恢复与路径诊断](../docs/netfs-recovery.md)。

Range 请求遇到连接中断、429、502/503/504 会有限重试；每次探测或 Range 填充任务最多重试 3 次、总时限 20 秒，直链刷新共用此预算。响应中断后，只有内容验证器保持一致才补取缺失后缀。平台只读 API 请求也有独立的有限重试，取消操作可中断等待。

路径可写相对挂载根的路径，也可写挂载点下的绝对路径。Go flag 规则要求选项写在路径之前。`status` 会在需要时启动索引并立即报告 `queued`、`scanning`、`complete` 或 `failed`；`wait-index` 持续等待直到完成，按 Ctrl+C 可取消。输出包含已发现成员数、扫描高水位和归档大小；无法精确统计时下载字节数显示为 `unknown`。退出码：`0` 表示查询成功或索引完成，`1` 表示用法、连接或路径错误，`2` 表示索引失败，`3` 表示等待超时，`130` 表示用户取消。

## 文件如何呈现

```text
~/mnt/123/
├── 普通目录/
│   └── 视频.mp4
└── 相册.zip/             # 保留 ZIP 文件名，但作为目录进入
    └── images/
        └── 001.jpg
```

`-zip-dirs=false` 可关闭映射，把所有支持的压缩包当作普通文件读取。目录列表完整翻页，云端单项查找、密码侧车发现和分卷发现按目录 ID 共享不可变快照，默认缓存 24 小时，可用 `-directory-ttl` 调整；压缩包内单项查找只构造目标成员，Readdir 仍列出完整目录；FUSE 属性与目录项缓存 1 秒。挂载通过内核 `ro` 选项拒绝写入、创建、重命名、删除，节点也拒绝写方式打开及属性修改。挂载过程只读取网盘；只有显式执行 `unlock` 子命令时才上传同级密码文件。

网盘允许同一目录中不同文件 ID 使用相同名称。挂载会保留全部条目：每组 ID 最小的保留原名，其余显示为 `名称 [id=文件ID].扩展名`（目录追加在完整名称后）。别名与已有名称冲突时增加序号，例如 `[id=123-2]`；长别名按 UTF-8 字符边界截短至 255 字节。同一组条目在 API 返回顺序改变后仍使用相同别名。仅挂载显示名称变化，网盘原名、文件 ID、压缩格式识别和密码/分卷发现仍使用原始元数据；密码文件或分卷自身存在歧义时仍拒绝自动选择。删除原名对应的文件后，刷新目录会让剩余 ID 最小的文件使用原名。

非零 `-root-id` 会在挂载前通过 Detail 验证为未删除目录；根 ID `0` 表示合成的“我的文件”根并跳过 Detail。FUSE `mtime`/`ctime` 使用云端更新时间；更新时间缺失时回退到创建时间。API 的无时区日期按中国标准时间 UTC+8 解释。

## 读取和缓存

- 普通云端文件和 ZIP Store 成员通过 HTTP Range 按需读取。远端数据以不可变范围片段写入磁盘缓存；常规读请求按 1 MiB 窗口获取，遇到缓存压力时会缩小请求，不必为了一个小读取保留整块。读取器按文件 ID、版本、大小和 HTTP 验证器识别内容，在 `-source-ttl`（默认 6 天）内复用。签名直链另按获取时间缓存 6 天，最多 4096 条；进程重启后按需重新获取，绝不写入磁盘。直链过期或返回 401/403/404/410 时刷新并重试一次。具有稳定内容版本，以及已验证强 ETag 或有效 Last-Modified 的来源可恢复持久身份，先读已缓存内容，遇到缺口再获取直链；详见 [缓存优先读取与阶段统计](../docs/netfs-cache-first.md)。
- 普通云文件和 ZIP Store 数据区使用消费驱动的字节预读。默认领先窗口上限为 16 MiB，每个句柄最多两个在途 Range；请求块从 512 KiB 起步，按读取等待、连续消费和预取命中反馈调整。已完成但尚未消费的数据也占领先窗口，避免快速来源在慢速读取时无限向前下载。远距离 seek 会取消旧预测窗口，关闭句柄会取消并等待预读。`-read-ahead-mib=0` 可关闭。打开、stat 和列目录不会触发预读；压缩成员仍由解压路径处理。反馈和指标定义见 [read-ahead design](../docs/netfs-readahead.md)。
- ZIP 进入目录时只读取中央目录，不会预先下载整个压缩包；查找单个成员只构造目标项，`Readdir` 仍生成完整列表。Store 成员直接定位数据区并支持随机读取。Deflate 和加密成员需要解压或解密；默认情况下，解压后达到 8 MiB 的 ZIP、加密 ZIP、7z 和 RAR 成员会边解压边提供已写入部分，`Open` 不等待全文件完成。请求未就绪的区间会等待该区间的数据，逐次读取遵循调用取消；读取包含最后一个字节时，还会等待最终校验与缓存发布，避免完整读取后立即关闭而丢失缓存或吞掉校验错误。校验成功前，早期字节可能已经交给读取端；后续读取可能报告 CRC、认证或解压错误。只有全成员成功完成并通过可用校验后才会发布为完整缓存。小于 8 MiB 的成员及 `-stream-members=false` 下的所有成员保持严格行为，必须完整解压和校验后才返回句柄。
- 严格打开并完整物化的归档成员默认可用 Linux 内核页缓存，`-archive-page-cache=false` 可关闭。仍在解压的大成员句柄使用 `DIRECT_IO`，即使填充随后完成也保持如此；再次打开已完整缓存的大成员时可使用内核页缓存；启用相邻图片预取时，图片同样保持 `DIRECT_IO`，让实际的正向或反向读取推动预取窗口。ZIP Store 成员和普通云文件按需读取，不启用内核页缓存。
- 下载中的 Range 会在目标字节写入临时文件后直接提供读取，不必等待大响应尾部或磁盘同步；只有完整响应通过版本、范围和长度校验后才原子发布持久缓存。HTTP 在途预算与临时范围/待发布预算分别记账，后者沿用下载预算配置并持有到同步完成。提前返回的字节无法撤回，后续传输错误仍会报告给等待后续字节的读取；归档成员末尾校验规则不变。详见 [渐进 Range 读取](../docs/netfs-progressive-ranges.md)。
- `-cache-gib` 默认限制磁盘缓存为 50 GiB，包含 Range 数据、已完整解压的成员、目录快照、版本化索引 DTO 和正在填充时预留的空间。优先淘汰未消费的预取数据，再淘汰只访问一遍的数据，反复访问的热点获得更高保留优先级；各等级内部按 LRU 淘汰。小型完整索引的保护份额为缓存容量的 1/8、最多 64 MiB，超过份额的索引仍可进入普通缓存。打开的缓存文件保持占用直到关闭；成员超出预算或没有可淘汰空间时返回 `ENOSPC`。旧缓存兼容，保留等级可跨重启恢复，详见 [缓存保留策略](../docs/netfs-cache-policy.md)。缓存是工作缓存；有效的根目录快照可免去列表请求，但非零挂载根的验证、未能恢复身份的文件源探测和未缓存内容仍需联网。
- `-cache-durability=durable` 是默认模式：缓存文件原子发布并同步到磁盘，Range 数据、目录快照和完整归档索引可在进程重启后复用。`-cache-durability=ephemeral` 将缓存对象写入私有临时子目录，省去文件同步，正常退出时删除；异常退出遗留目录会在下次启动清理，不会复用。两种模式都将 `token.json` 和控制 socket 放在选定的 `-cache-dir` 根目录；ephemeral 模式只丢弃缓存对象，不丢失令牌。
- 目录快照、归档索引、密码侧车结果和远端读取器元数据共用独立的内存预算，默认估算容量 64 MiB，可用 `-metadata-mib` 调整；按最近使用情况淘汰。该预算不属于 `-cache-gib`，也不是进程 RSS 的硬上限：活动节点、打开文件、解压器和构建时临时对象仍占内存。单份索引超出元数据预算会报错，可增大 `-metadata-mib` 或在适用时提高 `-archive-max-entries`。
- 成功完成的 ZIP/7z/RAR 索引以版本化 DTO 存入 durable 磁盘缓存并计入 `-cache-gib`。ZIP 保存中央目录成员信息和本地头偏移；RAR 保存可重新验证的成员定位记录。DTO 不含读取器、密码、解密状态或下载 URL；格式版本不兼容或身份验证失败时会重建。旧版成员缓存键不迁移到新的账户/密码身份空间，首次读取可重建；旧对象保留至正常 LRU 淘汰，不会误作新身份内容使用。索引按账户/API、File ID、内容版本和大小定位，并区分格式与密码；无 API 内容版本时回退到 HTTP 验证器，7z 分卷身份还包含卷的顺序、ID、版本和大小。名字、父目录和临时下载 URL 不作为索引身份，因此移动或同格式改名可复用索引。ZIP 内存索引不按目录 TTL 失效；7z/RAR 完整索引在内存中最长缓存 365 天，仍受 LRU 和 64 MiB 元数据预算约束。重启后优先恢复仍有效的来源身份；无法恢复时需联网检查源文件。ephemeral 模式不跨挂载保留这些索引。
- 目录快照（包括密码侧车与 7z 分卷发现）默认有效 24 小时，可用 `-directory-ttl` 调整；过期后首次访问使用旧的不可变快照，同时合并后台刷新，刷新完成后后续访问看到新内容。读取器复用时间由 `-source-ttl` 控制，默认 6 天。增大 TTL 可减少 API 请求，也会延迟外部修改的可见性；已打开的旧目录/文件句柄仍可保持原快照。
- durable 缓存目录使用权限为 `0600` 的 HMAC 身份密钥生成稳定索引与密码指纹；ephemeral 模式在自己的会话目录使用独立密钥，不复用上次挂载的缓存身份。密码、解密状态和签名下载 URL 不写入磁盘。密码在进程内使用每次挂载随机生成的密钥加密保存，密码侧车修改会在目录快照刷新后生效。

普通文件时间默认来自目录 List 元数据，不额外查询每个文件；`Getattr` 使用 inode 持有的不可变快照。可启用 `-file-info`，让 Lookup 对活跃云端条目按需调用 Infos，最多每批 100 个 ID，并按元数据 TTL 缓存结果。它能发现已删除条目并刷新云端时间，但会增加 API 请求，因此大目录 `find`/遍历可能更慢；默认关闭。读取过程中若文件大小或版本与父目录快照不一致，Lookup 返回 `ESTALE`，等待目录快照 TTL 后重新查找。Infos 队列最多等待 400 个条目，批次受 5 ms 合并窗口和最多 4 个元数据构建并发限制；请求取消会退出等待，全部批次请求取消时也会取消 API 请求。遇到 429 最多重试 4 次；服务端要求等待超过 30 秒时返回错误。

`ls -l` 使用目录句柄的同一份快照补充属性和稳定 inode，避免逐项重复查询来源、密码和归档索引；重新打开目录可以看到已刷新的内容。打开目录保留的快照另受 `-metadata-mib` 大小的全局预算约束，相同快照共享计费，关闭句柄释放；保留空间不足时返回 `ENOMEM`。RAR 只冻结当前层已发现的成员，不持有整个增长中的索引。实现与本地测量见 [目录快照说明](../docs/netfs-directory.md)。

普通读取和索引构建会响应操作取消。流式成员的解压任务由挂载生命周期和仍打开的成员句柄共同持有：取消一次 Read 只会停止该次等待；最后一个句柄关闭时取消未完成的成员解压，卸载时取消所有任务。7z 的有界组缓存会在短读关闭后继续完成该组，最长 5 分钟；组级填充与单个成员填充分开管理。严格模式下，共用缓存填充若由已取消的请求发起，仍在等待的请求可以重新发起。

## 支持边界

支持普通文件、单卷 ZIP（Store / Deflate，包括标准库支持的 ZIP64）以及采用 AES 或 ZipCrypto 加密成员的 ZIP。另支持 7z、7z 分卷（从 `.7z.001` 进入）、单卷 RAR，包括加密目录、加密成员和固实压缩。传统加密使用 [yeka/zip](https://github.com/yeka/zip) 的分块解密状态机，AES 使用 Go 标准密码库和 PBKDF2，支持 128/192/256 位、AE-1/AE-2。压缩成员的打开和逐段读取行为见“读取和缓存”：大成员可以在解压过程中先交付已生成的明文，完整校验通过后才发布完整缓存。ZIP 加密中央目录、ZIP 的其他压缩算法、分卷 ZIP、分卷 RAR、嵌套压缩包自动映射暂不支持。ZIP 内部的另一个 ZIP 作为普通成员文件读取。

7z 使用纯 Go 库 [bodgit/sevenzip 的维护 fork](https://github.com/binghezhouke/sevenzip)，基于上游 `v1.6.1` 增加组级读取与成员偏移接口，固定版本和扩展边界见[维护说明](../docs/sevenzip-fork.md)。RAR 使用 [nwaples/rardecode](https://github.com/nwaples/rardecode)，运行时无需 `7z` / `unrar` 命令。7z/RAR 从同级 `文件名.7z.pwd` / `文件名.rar.pwd` 读取密码；7z 分卷共用 `文件名.7z.pwd`，要求所有卷在同一网盘目录、从 001 连续编号，最多 1000 卷。只有 `.7z.001` 映射为目录，后续卷保留为普通文件。分卷按需获取直链和读取，缓存键包含整组分卷版本。

7z 的同一固实组共享解压缓存，已经经过的前序字节也会保留；不同成员及并发读取合并为一次组填充。完整组通过可用 CRC 校验后持久化，按账户、内容版本、密码和分卷身份隔离。单组最大 `min(1 GiB, 总缓存容量 / 4)`，计入 `-cache-gib`；更大的组或无法预留组缓存空间时回退按成员解压。首次冷读靠后成员仍需解码组内前序数据，后续同组读取可从本地组缓存直接取出。

组缓存填充的 7z 正文按独立 packed 输入使用最大 8 MiB HTTP 窗口，解码器仍小块读取，下载中的数据从磁盘 staging 渐进供给。消费一半时可提前启动下一窗口；每个输入最多当前和下一窗口，所有输入合计最多 16 MiB，并按缓存容量进一步缩小。范围在输入与分卷边界截断，不为预读解码其他组；头部索引保持原有读取方式。已消费窗口的最终 HTTP 校验通过后才发布组缓存，窗口首次空间预留失败时缩小窗口；读出数据后发生的容量或磁盘错误仍可能中止填充。分卷仅合并来源初始化，网络读取可并行。参见 [#43 验收记录](live-validation.md)。

7z/RAR 成员首次读取会从归档中解压到私有缓存；大成员默认可逐段读取，小成员或关闭流式读取时须先完整解压。完整结果经过大小检查及解码器提供的完整性校验后才进入缓存。固实包打开靠后的成员可能解压前序数据，所以读取尾部可能较慢，不能保证即时播放。索引解析默认有 64 MiB 读取预算（提高 `-archive-max-entries` 时按每条 512 字节增加，取两者较大值），RAR 解码字典上限为 64 MiB，索引构建和成员解压共用最多 4 个并发槽；超过预算返回错误。成员解压空间计入 `-cache-gib`，空间不足返回 `ENOSPC`。所有格式都拒绝链接、特殊文件和不安全路径。密码缺失或错误时，加密目录或严格打开的成员返回 `EACCES`；流式打开后的解密失败通过后续 `Read` 报告错误；终端不会自动弹出密码输入。网页生成的 `.pwd` 可直接使用。密码及不存在密码文件的结果与目录快照共享默认 24 小时 TTL；过期后先用旧快照，后台刷新完成后后续访问生效。

加密 ZIP 需要一个与压缩包同目录、命名为 `<archive name>.pwd` 的云端普通文件作为密码侧车。中央目录未加密时，仍可进入 ZIP 目录并列出成员；读取成员需要正确密码。缺少侧车时成员打开返回 `EACCES`；错误密码在严格模式的打开阶段拒绝，在流式模式可延迟到读取阶段报告。挂载不会提示输入密码。设置 `-zip-dirs=false` 后，所有格式均作为原始压缩文件读取。侧车密码按目录快照 TTL（默认 24 小时）自动读取；自动读取的密码只保存在进程内存。用户通过普通文件方式打开 `.pwd` 侧车时，它会像其他云端文件一样进入磁盘缓存。侧车本身按用户要求以明文保存在云盘中。

挂载时每个具体成员仍会使用当前侧车密码解密；若压缩包中成员使用不同密码，该成员会在打开或流式读取时报告错误。加密中央目录尚不支持。

`unlock` 子命令目前用于 ZIP，可验证密码并创建或替换侧车；7z/RAR 请先在网页验证并生成 `.pwd`。密码不会作为命令行参数传递：默认在终端隐藏输入，也可从标准输入读取。该命令会先完整验证一个最小的加密成员，只有验证成功后才上传密码。为了避免密码写入 shell 历史，标准输入示例使用权限受限的文件作为密码来源：

```bash
./mount123 unlock -file-id 12345 -config ../config.json
./mount123 unlock -file-id 12345 -password-stdin -config ../config.json < /path/to/password.txt
```

`-cache-dir` 可指定现有私有缓存根目录；命令复用其中的 `token.json`，并在根目录下建立临时私有缓存目录，磁盘缓存上限为 256 MiB，退出时删除。无有效侧车或密码错误时挂载不会弹出输入提示。

要求下载源返回正确的 HTTP 206 和 Content-Range；不支持 Range 时明确失败，不会悄悄下载整个大文件。读取期间实体验证器变化会报错，避免拼接不同版本。源站完全不提供验证器时无法保证读取期间源文件不变。Store 随机读取不做全成员 CRC 扫描；Deflate 成员只有完整解压时才能完成 CRC 校验。

ZIP 名称优先使用 UTF-8 标记或 CRC 校验通过的 Unicode Path 扩展字段；未标记且非 UTF-8 的旧名称尝试 GB18030，再回退 CP437。旧编码没有可靠标记时仍存在识别歧义；拒绝路径穿越、符号链接、重名和文件/目录冲突。ZIP 最多 100,000 条中央目录记录，命令行挂载展开后的文件和隐式目录合计默认最多 200,000 个节点，路径深度最多 128，累计名称预算 16 MiB，中央目录编码大小上限 64 MiB。解析前预检真实记录数，预检及标准库解析每遍另留有限尾部记录读取余量；不对成员文件设置额外的 32 MiB 限制。索引 DTO 与缓存的 Range 数据计入磁盘缓存预算；内存索引副本、令牌文件及文件系统元数据开销不计入 `-cache-gib`。

```bash
go test -race ./...
go vet ./...
# 真实 FUSE 挂载，使用本地模拟 API 数据，不访问个人网盘：
MOUNT123_FUSE_TEST=1 go test -race -run TestActualFUSEMount -v ./internal/mountfs
```

测试覆盖 API 授权/分页、缓存预算与并发、HTTP Range 验证、普通文件和 ZIP 随机读取，以及实际挂载后的写入/创建/删除/重命名拒绝。缓存维护性能可用固定大小、固定成员数的本地样本比较：先预热，再重复读取相同成员和超出预算的轮转工作集；记录总耗时、Range 请求次数/字节，以及 `strace -f -c -e trace=utimensat,fsync,rename,unlink` 的系统调用次数。分别测试 durable 与 ephemeral，重挂载复用单独记录，避免把热缓存结果当作冷下载速度。LRU 使用链表维护，访问时间最多每分钟写入一次；大量句柄仍在使用时淘汰需跳过这些条目。真实网盘验收结果见[验收记录](live-validation.md)。

## 图片启发式预取

默认启用相邻图片预取，参数 `-prefetch-files=9 -prefetch-workers=2 -prefetch-mib=256`。实际读到图片数据后，同目录按自然文件名排序预测下一张，首次取后面 2 张，连续同向浏览扩大到 4、9 张；反向时取前面的图片，跳跃时缩小窗口。每次继续浏览都会推进预取窗口。普通目录和 ZIP 均可预取；7z 支持组缓存时只预取预测窗口内同组图片，并按解压偏移调度，避免同时启动多个无关组。其他 7z 和 RAR 每轮最多预取 1 张。

只有实际读取图片才触发，`ls`、`stat`、仅打开不读取及普通 `find` 不触发；缩略图程序实际读图可能触发，无法确定用户的界面排序。启用预取时图片保持 `DIRECT_IO`，让每次实际读取都进入 FUSE 并推进正向或反向预取窗口。新的前台打开若命中正在预取的目标则复用填充，否则取消旧预取，后台任务最多运行 30 秒，不递归触发更多预取。256 MiB 是每轮目标图片总大小预算，超预算图片只跳过预取，前台读取不受此限制；固实包的前序读取量可能更大。复用现有磁盘缓存与并发填充合并，预取失败不影响正常读取。`-prefetch-files=0` 可完全关闭。该功能是跨图片预测，与单文件字节级自适应预读分别控制。

详细设计与参考资料见 [挂载图片预取设计](../docs/design/mount-prefetch.md)。

## ISO 光盘镜像目录

默认启用 `-iso-dirs=true`，云目录中的 `.iso` / `.ISO` 可直接作为只读目录进入。支持 ISO9660、Joliet 中文长文件名、Rock Ridge 和常见 UDF（含元数据分区）；桥接镜像优先使用 UDF。`-iso-dirs=false` 恢复原始文件读取，与 `-zip-dirs` 独立。

进入时只读取卷与所需目录元数据，内部文件通过直链 Range 按需读取，并复用现有缓存、顺序预读及相邻图片预取。普通文件无需完整下载镜像，也无需 root、loop 设备或为每个镜像另行挂载。镜像内的归档或另一份镜像暂时作为普通文件呈现。

本版尚不支持多 extent ISO Level 3、交错 ISO、Rock Ridge SF/zisofs ZF 数据和 UDF virtual/sparable 分区，遇到这些布局会报错；UDF 多区间文件、稀疏洞和 Blu-ray 实时文件（M2TS/SSIF）按分区映射读取。UDF 库的本地补丁支持有界的长分配链，已验证真实 9.8 GB 成员的尾部随机读取。不会解密 DVD/Blu-ray 内容保护。格式边界、缓存及库选型见 [只读光盘镜像设计](../docs/design/mount-disc-images.md)。

## 大型 RAR 首次列目录

RAR 的文件头分散在成员数据之间，首次列目录必须逐个扫描，不能像 ZIP 一样只读尾部中央目录。大量小文件的 RAR 即使不解压内容，也可能需要很长时间。扫描使用 512 字节解析缓冲；起初以 64 KiB 小块读取并复用已有的 1 MiB 数据块。连续三次读取位置相距不超过 1 MiB 时，按 1→4→16 MiB 扩大连续读取窗口，每个窗口只发一个 HTTP Range 请求，并缓存至磁盘与当前扫描的内存。遇到超过 1 MiB 的跳跃时停止扩大窗口，已在窗口内的数据仍复用，后续按稀疏模式重新判断。密集小文件包因此会多下载一部分正文，以减少串行请求次数；通过基于 `rardecode` 的逐条文件头回调跳过成员数据，固实包列目录也不解压前序成员。成功跳转后的 CDN 地址在当前读取器内复用。

7z/RAR 索引扫描由后台任务执行，同一索引的请求合并。等待完整索引的操作超过 5 秒返回 `EAGAIN`（终端通常显示 `Resource temporarily unavailable`），后台继续构建；RAR 的交互目录浏览使用下文的快照方式，无需等待完整索引；取消前台请求不会丢弃扫描进度。最多 4 个后台索引任务，每次最长 30 分钟，卸载会取消任务。日志每 30 秒记录 RAR 扫描位置：`offset` 是当前读取位置，`size` 是整个压缩包大小，单位均为字节。可用 `offset / size` 观察位置推进；两者都不表示累计下载量或解压量。根目录的 `cd` 不必等待列目录，普通 `ls` 使用下文的部分目录快照。

大目录可提高 `-metadata-mib` 和 `-archive-max-entries`（默认 100000，最多 1000000），展开节点上限为条目上限的两倍。增加限制不会消除首次扫描所需的网络往返。

### RAR 渐进式目录

RAR 扫描发现成员后立即发布对应文件与隐式父目录。**每次打开目录取得当时已发现条目的固定快照**，普通 `ls` 排序并输出该快照后立即结束，不等待整个归档扫描；再次 `ls` 会看到新增项目。同一目录句柄中新增条目不会改变原快照，重置游标也保持一致。

已发现的目录可立即进入，已发现的文件可直接查询或打开。尚未扫描到的名字返回 `EAGAIN`，不提前报告 `ENOENT`，避免 Git 提示符等探测把终端拖住。如果尚未发现任何条目，最多等待第一批 1 秒，再返回 `EAGAIN`；该等待不包含首次 API/直链准备。扫描完成后，新的目录快照就是完整列表。

索引完成前，`ls`、`find` 等遍历看到的都是当时已发现的部分内容，不能据此判断全包文件数；这是为了快速交互浏览而采用的快照语义。无需专门使用 `ls -U`。7z 仍先解析其集中存储的头部索引，未承诺渐进解码其索引。

`third_party/rardecode` 保留 v2.2.1 的原始源码和许可证，只在 `walk.go` 中增加文件头遍历、位置记录和定点打开接口，以便不解压固实正文也能逐条发布文件头。具体改动见该目录的 `LOCAL_CHANGES.md`。

### RAR 成员首次读取与元数据刷新

RAR 索引同时保存成员头的位置。非固实成员首次打开时读取归档前导头、直接跳到目标头部，使用当前密码重新解析，然后仅解压该成员并校验；不再按成员序号从头遍历。定位记录不含密码、解密密钥或读取器。固实成员仍可能依赖前序解压，不能保证相同的首次读取速度。

已有云端目录列表、密码侧车信息（包括不存在侧车的结果）超过刷新周期后，当前操作先使用已有快照，后台合并刷新；最多 4 个刷新任务，45 秒超时。成功后后续访问使用新快照；云端目录刷新遇到临时网络故障时保留旧快照并退避，永久错误移除旧目录快照；密码侧车信息沿用失败后重新加载的行为。首次缓存缺失仍需请求网盘。外部修改的可见时间因此包含后台刷新耗时，而不仅是默认 24 小时；已打开的旧文件快照不被替换。

### 前台任务优先

归档后台扫描、过期元数据刷新和图片预取标记为后台工作。构建/解压默认最多 4 个任务，其中最多 3 个后台任务。平台 API 限流与已获得直链后的 HTTP 下载分开：下载默认最多 32 个请求、全局在途响应预算 128 MiB，并给前台保留 1 个请求槽和 16 MiB。可分别通过 `-download-requests`、`-download-bytes-mib`、`-download-foreground-reserve-mib` 调整；大请求同时受字节预算约束。这些是可调初值，不代表真实网盘的最优参数。

下载队列按文件轮转，前台优先，并在连续前台授予后给后台推进机会；已经开始的 HTTP 请求不强制抢占。前台加入已有后台范围下载时，会提升其排队和后续请求优先级，共享下载不会因单个等待者退出而取消。请求数和在途响应字节是资源上限，不是平台 API QPS、带宽速率或 Go 内存用量。调度规则与测试见 [下载调度说明](../docs/netfs-scheduling.md)。
