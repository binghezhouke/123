# 123 云盘工具箱

围绕 [123 云盘开放平台](https://123yunpan.yuque.com/org-wiki-123yunpan-muaork/cr6ced)（`open-api.123pan.com`）的三件套：

| 组成 | 位置 | 说明 |
| --- | --- | --- |
| **API 客户端库** | `api/` | 封装认证、限流重试、文件列表/搜索/详情、秒传与上传、WebDAV 直链、Redis 缓存 |
| **Web 文件浏览器** | `app.py` `routes/` `templates/` | Flask 应用，浏览、搜索、查看详情、取下载链接 |
| **批量上传脚本** | `upload_core.py` + 三个 CLI | 本地目录上传、清单秒传、批量秒传 |

## 快速开始

```bash
# 1. 安装依赖（需要 uv）
uv sync

# 2. 准备配置
cp config.json.template config.json
$EDITOR config.json          # 填入开放平台的 CLIENT_ID / CLIENT_SECRET

# 3. 启动 Web 浏览器
uv run python app.py         # http://localhost:8081
```

Redis 是可选依赖：连不上时会自动降级为不使用缓存，只是文件详情查询会多打几次接口。

## 配置说明（`config.json`）

| 键 | 必填 | 说明 |
| --- | --- | --- |
| `CLIENT_ID` / `CLIENT_SECRET` | 是 | 开放平台应用凭据 |
| `SECRET_KEY` | 否 | Flask session 密钥，不用 session 时无所谓 |
| `REDIS.ENABLED` | 否 | 为 `false` 或连不上时不使用缓存 |
| `REDIS.HOST` / `PORT` / `DB` / `PASSWORD` | 否 | Redis 连接参数；不写这一段则回退到 `localhost:6379`（命令行脚本和 Web 应用都按这里读） |
| `WEBDAV.ENABLED` | 否 | 是否启用 WebDAV 直链功能 |
| `WEBDAV.USERNAME` / `PASSWORD` | 启用时必填 | WebDAV 账号（早期模板里叫 `USER`，仍兼容） |
| `WEBDAV.BASE_URL` | 启用时必填 | 形如 `https://webdav-xxxx.pd1.123pan.cn`（早期模板里叫 `HOST`） |
| `WEBDAV.PATH_PREFIX` | 否 | URL 路径前缀，默认 `/webdav` |

`config.json` 已在 `.gitignore` 里，不要提交（也不要写进任何 md 文档里）。

## 命令行工具

三个脚本共用 `upload_core.py`，秒传口径完全一致。

### 上传本地目录

```bash
uv run python upload_folder.py /path/to/folder 远程/子目录
uv run python upload_folder.py /path/to/folder --dry-run     # 只打印计划
uv run python upload_folder.py /path/to/folder -j 8          # 并发上传线程数
```

处理顺序（与清单上传同一套思路）：

1. **串行准备目录**：逐级创建并缓存目录ID，已存在的目录从快照取 ID，不发 mkdir
2. **快照判重**：同名同大小文件零请求跳过（目录在解析时已列过一次）
3. **并发上传**：每个文件先试 SHA1 秒传，未命中再走分片上传；实际请求速率仍受 `--rate` 限制
4. **失败重试**：失败的串行重试一轮，仍失败才计入失败

### 从清单秒传

清单支持两种格式：

- JSON：`{"commonPath": "远程/目录", "files": [{"path": "a/b.txt", "size": 123, "etag": "<md5或sha1>"}]}`
- 123 云盘导出文本：`etag#size#path$etag#size#path$...`

```bash
uv run python upload_from_json.py files.json
uv run python upload_from_json.py files.json -d 目标目录 -w 16 --rate 10
uv run python upload_from_json.py files.json --tree 目录树.txt
```

处理顺序（越靠前越省接口调用，也越不容易撞限流）：

1. **目录树预筛**（`--tree`）：传了目录树导出文件就先按文件名零请求地筛掉已上传的，连目标目录都不用列
2. **并发秒传**：未传 `--tree` 时不主动列目标目录判重，直接按清单处理；传了目录树时，剩余文件按 `--rate` 限速并发处理
3. **失败重试**：失败的串行重试一轮，仍失败才计入失败

传入 `--tree` 时，判重优先使用目录树导出的云端快照（`--tree-verify` 会进一步查询核实），不依赖任何本地"已完成"记录；未传时默认不做目录判重。

判重规则（默认"宽松"）：

- 清单里的哈希能解出 **MD5**，且与云端记录一致 → 确定是同一文件，跳过
- 清单只有 **SHA1**（没法直接比 MD5）→ 同目录 + 同名 + 同大小即跳过，日志会标注"未校验内容"；
  想每次都发请求校验用 `--verify`
- 同名同大小但 **MD5 不一致** → 不静默跳过、也不造重复文件，单独列为"内容冲突"等你确认

**目录树预筛（`--tree`）**：网页端对目标文件夹"导出目录树"得到 txt，传给 `--tree`，
判重就先按"这个位置有没有这个文件名"零请求地筛一遍——目录树里已有的直接跳过，
全部命中时一个请求都不发；目录树里没有的才解析目标目录、走秒传。两点注意：

- 导出的目录树**只有文件名**，校验不了大小和内容（同名不同版本的文件会被跳过）；
  要稳妥加 `--tree-verify`，让命中的条目再列目录按大小/MD5 核实
- 目录树是导出那一刻的快照，云端之后的变化它看不到——上传前现导出即可。
  重跑会按最新导出重新判

导出根默认按首行是"我的文件" = 网盘根来换算；别的对应关系用 `--tree-root` 指定。
目录树文件也可以是带大小/哈希的清单文本（`etag#size#path$...`），那种会自动按
大小 + MD5 的严格口径判重。


相关开关：

| 参数 | 作用 |
| --- | --- |
| `--rate N` | 每秒请求数上限，默认 8；`0` 表示不限速 |
| `--tree FILE` | 目录树导出文件，先按文件名零请求预筛已上传的文件 |
| `--tree-root PATH` | 目录树根对应的远程路径（默认：首行，"我的文件" 视为网盘根） |
| `--tree-verify` | 目录树名字命中后仍列目录核实大小/MD5（默认直接跳过） |
| `--no-dedup` | 兼容旧参数；未传 `--tree` 时默认不去重，目录树预筛不受此开关影响 |
| `--verify` | 清单只有 SHA1 时也发请求确认，而不是按同名同大小跳过 |
| `-v` / `--verbose` | 逐条打印每个文件的结果 |

**输出默认是紧凑的**：整个运行过程是一块两行的进度区（终端里原地刷新），第一行是当前阶段
（准备目录 / 判重 / 秒传 / 重试）和正在读取的目录，第二行是整体进度条。进度条的分母始终是
清单总条数，判重解决一条、秒传完成一条都算 +1，所以阶段切换时进度不会归零重来。按阶段推进
速率估的"剩 X"：判重/建目录阶段显示在第一行（那时进度条基本不动），秒传阶段显示在第二行
（和进度条同一个口径）。逐条明细只在 `-v` 时打印；失败项和"内容冲突"永远会逐条打印，
未命中的文件在汇总里最多列出 10 条（其余写 `-v` 查看）。

```
🔍 判重 1,203/5,000 · 12.3/s · 剩 05:12 · 📂 读取目录快照 /图片（第 2 页）
▶ 1,180/5,000 [██████░░░░░░░░░░] 24% · ✓ 1,157 ⏭ 23

⚡ 秒传 8 并发
▶ 3,300/5,000 [█████████████░░░░░] 66% · ✓ 2,100 ⚠ 12 ⏭ 1,188 · 6.4/s · 剩 04:21
```

输出被重定向到文件/管道时，同一个进度区退化成"换目录/换阶段时打印一行、长时间无变化按
5 秒补一次"，所以日志里也能看出进展。

### 批量秒传

```bash
uv run python batch_upload.py /path/to/manifest_dir -d 远程前缀目录 -w 16
```

每个清单都会处理，没有本地"已完成"记录可跳——判重靠 `--tree` 预筛或现列目标目录。目录树缓存和目录快照跨清单复用：同一棵目录树只建一次，同一个目录只列一次；`--tree` 所有清单共用一份。

每个清单处理完打一行明细（总数、已有多少、秒传多少）：

```
[3/8] 处理: 电影_346.5T.json
  ✅ 完成 (83.2s) 合计 123,456 条：已有 122,000（目录树 121,000，MD5 一致 1,000），秒传 1,450，未命中 5，失败 1
```

### 核对备份清单

```bash
uv run python reconcile_backups.py manifest.json report.json
```

将包含 `files` 数组的本地清单与远程 `/backups` 按相对路径、大小和 MD5/etag 比较，
报告输出已匹配、缺失和不一致的文件；不会修改云端文件。

### 结果口径

| 结果 | 含义 |
| --- | --- |
| 已有 | 云端已有该文件而未发请求：目录树按名 / 列目录 MD5 一致 / 同名同大小（未校验内容） |
| 秒传 | 发了秒传请求并命中 |
| 未命中 | 接口**正常返回**，但云端没有可复用的文件（需要常规上传，本工具不做） |
| 失败 | 调用本身出错（网络/业务错误码），**不代表**云端没有这个文件 |
| 其他跳过 | 记录不完整（缺路径/哈希）、目录创建失败、内容冲突 |

> 秒传接口只有 `reuse=true` 算成功。异常和"未命中"必须分开统计，否则失败会被误报成"云端没有该文件"。

## Web 文件浏览

### 文件预览与路径导航
点击图片、音视频、PDF 或文本文件直接预览内容，详情通过“文件信息”进入。
图片/PDF/音视频由后端流式转发 API 下载链接，支持媒体 Range 请求；能否播放取决于浏览器的编解码支持。
文本预览上限 2 MiB，HTML/SVG 作为纯文本展示。点击 ZIP/7z/RAR 直接打开压缩包目录。
顶部路径栏显示各级文件夹名称，可逐级返回；压缩包内部也有逐级路径链接。

**缓存范围**：文件元数据仍使用 Redis（可选，默认 TTL 1 小时）；Web 目录页新增每应用进程的
30 秒缓存，最多 128 页，按目录、页大小、分页游标区分；刷新按钮强制更新当前目录及路径元数据。
多进程之间不共享目录页缓存，搜索结果不缓存；压缩包直链和索引使用每进程 5 分钟缓存（最多 16 个压缩包、64 MiB 索引数据），图片仅在当前浏览器弹窗内预取缓存。
Redis 不可用时文件元数据查询回退到 API，目录页短时缓存仍生效。

### ZIP / 7z / RAR 只读浏览

在 Web 文件浏览器中点击压缩包即可进入包内目录，
在当前页面连续浏览同目录图片（上一张/下一张、左右方向键、手机左右滑动、Esc 关闭），
在新标签页打开文本/PDF，或下载单个文件。图片浏览器跟随翻页方向滚动预读 9 张：向后翻预取后面的图片，向前翻预取前面的图片（后台最多同时下载 2 张，翻页后继续补齐，切换方向时取消超出新窗口的请求），最多缓存 30 张图片或 256 MiB Blob 数据，按 LRU 淘汰，关闭时释放。HTML、SVG 和代码按纯文本显示；
其他格式提供下载。不提供压缩包内容的新增、修改或删除。

ZIP 浏览直接通过 API 获取下载链接，不尝试 WebDAV。
后端使用下载链接的 HTTP Range 按需读取目录索引和选中文件，不解压到磁盘。
选中文件的压缩数据按最大 8 MiB 的块读取，再在本地解压，减少小块读取的网络往返。
下载服务必须返回有效的 `206 / Content-Range`；不支持时显示提示，不自动下载整个 ZIP。
支持普通 ZIP、ZIP64，以及 Store / Deflate 文件；支持传统 ZipCrypto 和 AES 加密；暂不支持分卷 ZIP。
文件名优先使用 UTF-8 标记或校验有效的 Unicode 名称字段；未标记时尝试 UTF-8 和含中文的 GB18030，
否则保留 CP437。未标记编码的自动识别存在歧义；名称修正不改变解压时使用的原始索引。
文本预览识别 UTF-8/UTF-16/UTF-32 的 BOM，无 BOM 时尝试 UTF-8、GB18030；下载保留原始字节。
除图片及下述可直接播放的视频外，单文件的压缩大小和解压大小均限制为 32 MiB；目录索引限制为 8 MiB，条目最多 20000 个。
同一压缩包的直链与原始索引数据缓存 5 分钟，并发首次加载合并为一次；解析器与读取游标按请求独立创建。
链接返回 401/403/404/410 时清理缓存，重新获取一次；刷新按钮可强制重建索引。
读取过程中校验大小及 ETag/Last-Modified，文件变化则要求刷新目录；预览链接携带索引版本，防止旧编号对应到新文件。
服务端未提供版本校验头时仅复用直链，每次重新读取索引。应用的读取预算为 60 秒，单次网络读取另有超时。

**ZIP 视频播放**：对未加密、Store（仅打包）的 MP4/M4V/WebM/MOV，目录提供“播放视频”。
播放器按需请求成员内部的字节范围，后端映射到 ZIP 直链；支持拖动进度、尾部读取及下载。
这条路径不受 32 MiB 成员限制，不会先下载整个视频或压缩包；每块最多 256 KiB，关闭请求即释放连接。
复用已有直链和索引缓存，并校验上游文件版本；不对局部读取执行整个成员的 CRC 校验。
未加密的 Deflate MP4/M4V 可在目录弹窗内播放：后端仅转发该成员的压缩字节，浏览器 Worker 解压，
通过 MP4Box.js 将解压数据转换为 MediaSource 分段，索引在前部且编码受支持的视频可边解压边播放。
播放器消费完当前分块后才继续传递下一块，避免持续堆积播放队列。
索引不在前 1 MiB、分片 MP4、编码不受支持或 MediaSource 出错时自动回退为完整准备后播放。
完成时验证压缩流结束、实际大小和 CRC 后生成 Blob；提前播放阶段完整性尚未确认，校验失败即停止并清理播放器。
压缩大小和解压大小均不得超过 64 MiB；显示准备进度，支持取消、重试及准备完成后的下载。
同一页面最多运行一个任务、保留一个视频缓存；关闭弹窗后再打开可复用，切换视频或离开页面会释放。
缓存不持久化；Blob 构造及播放期间的实际内存可能超过文件大小，64 MiB 是文件上限，并非总内存上限。
无需 Service Worker 或 HTTPS，适用于局域网 HTTP；解压及分段组件使用随项目提供的 pako 2.1.0 / MP4Box.js 2.4.1，许可证见 `static/js/vendor/`。
其他压缩格式、加密及 7z/RAR 内视频暂不支持直接播放，仍可按原有限制下载。
没有服务端转码，实际播放能力取决于浏览器支持的视频和音频编码。

7z/RAR：支持非固实、单卷压缩包的目录浏览、单文件预览和下载；
固实包仅展示目录并提示下载原文件。RAR 压缩文件解压需要系统安装 `unrar`
（`rarfile` 也可使用受支持的其他后端）；缺少工具时会提示错误。RAR 会创建临时单文件压缩包，
解压后清理，不按包内路径写出文件。读取仍通过 API 下载链接的 Range 请求。

依赖更新：运行 `uv sync` 后重启应用。自动测试包含真实 RAR 样本及生成的 7z 包；
带 `unrar` / `7z` 的环境还会执行对应解压和大文件跳读验证。

同目录的 **7z 分卷**（`name.7z.001`、`.002`……）也支持浏览：点击任意一卷，
自动分页查找同组分卷，按编号建立可跨卷读取的逻辑文件；用到哪一卷才获取该卷的 API 直链。
分卷编号必须从 001 连续，最多 1000 卷；缺号、重复编号和缺少末卷时显示错误提示。
整组分卷共享 5 分钟索引/直链缓存，单卷直链失效时重新发现整组并刷新一次。
非固实分卷支持预览、下载和图片预取；固实分卷只浏览目录，支持输入密码解密（包括加密目录）。

加密压缩包会提示输入密码；ZIP、7z 和 7z 分卷解密后可继续预览、下载和图片预取。
密码仅保存在服务端进程内存，按浏览器会话及压缩包隔离，15 分钟后过期，
可通过“清除密码”立即删除；不会写入 URL、Cookie 或磁盘。重启服务后需重新输入。
多进程部署需要会话粘滞路由，否则不同进程可能再次要求输入密码。
RAR 支持加密目录，但加密文件提取受解压工具限制，需要完整读取压缩包，
因此仅对总大小不超过 32 MiB 的非固实加密 RAR 启用预览；较大的包会提示下载。
RAR 仍需要系统安装 `unrar` 或兼容解压工具。固实压缩包仍仅支持目录浏览。

## 目录结构

```
api/                     客户端库（唯一公共入口是 api.client.Pan123Client）
  client.py              对外统一接口，委托给下面几个模块
  auth.py                token 获取/缓存（缓存固定在 ~/.cache/pan123_api/token.json）
  http_client.py         统一重试（5xx、业务码 1/429/20103）与可选限速
  ratelimit.py           令牌桶限速器
  file_service.py        文件列表/路径/上传/秒传/WebDAV
  cache.py               Redis 文件元数据缓存（JSON 序列化）
  models.py              File / FileList
  config.py              config.json 解析
routes/                  Flask 蓝图（main 页面 / api 接口）
templates/ static/       前端
upload_core.py           上传公共逻辑：清单解析、哈希归一化、目录树、秒传、统计
tests/                   pytest 测试（不依赖网络/Redis/真实配置）
```

## 注意事项与已知限制

- **token 上限**：同一 `client_id` 最多同时存在 3 个 token（有效期 30 天）。token 缓存固定在 `~/.cache/pan123_api/token.json`（权限 0600），这样从不同目录运行也共用同一个 token，不会互相挤掉。
- **接口限流**：限流是**账号级**的。实测同时并发超过约 8 个请求，接口会返回 HTTP 200 + 业务码 1（"请慢一点"）；再加线程也不会更快，吞吐封顶约 8 请求/秒。所以秒传按速率节流而不是堆并发，业务码 1 会被自动退避重试。目录创建保持串行（mkdir 另有 20 QPS 限制）。
- **目录缓存**：`FileService` 的目录/目录ID缓存只在本进程内有效，重启后重建。
- **Web 端没有鉴权**：`app.py` 默认监听 `0.0.0.0`，同网段任何人都能浏览云盘。长期运行请放在带认证的反向代理后面，或设 `FLASK_HOST=127.0.0.1`。调试模式默认关闭，需要时用 `FLASK_DEBUG=1` 临时开启（Werkzeug 调试器可执行任意代码，不要对外暴露）。
- **WebDAV 直链含明文密码**：详情页展示的 WebDAV URL 里带着账号密码，只在本机使用，不要外发。日志里已做脱敏。
- **单文件限制**：分片上传路径按官方文档的单文件 10GB 设计，实际可用额度取决于账号权益包。

### 彩色收藏

文件图标、列表和搜索结果旁的 ☆ 可选择红、橙、黄、绿、蓝、紫、灰七种收藏颜色；已收藏项显示对应圆点，点击可换色或取消。
侧栏与顶部工具栏提供收藏入口，收藏页可按颜色筛选。支持文件夹及压缩包内文件；压缩包内收藏返回所在目录，定位到该条目。
收藏按文件 ID（包内条目另带索引版本）识别，加载更多后自动恢复标记。数据保存在当前站点的浏览器 localStorage，刷新和重启浏览器后保留，同浏览器标签页同步。
不跨设备同步；清除浏览器站点数据会清除收藏，云端删除文件不会自动移除收藏。

文件列表、搜索列表和压缩包目录支持拖动表头右边界调整列宽；双击边界恢复默认宽度。
聚焦边界后可用左右方向键微调（Shift 加快），Home 缩至最小宽度，拖动时 Esc 取消。
列宽保存在当前浏览器，各列表类型及不同屏幕布局分别记忆；加载更多的条目自动沿用当前列宽，过宽时可横向滚动。

无扩展名或后缀不可信的文件，可在文件信息页点击“探测压缩格式”。只有主动点击才读取最多前 8 字节（使用 API 直链的 Range 请求），识别 ZIP / 7z / RAR 后显示“浏览压缩包内容”入口，不自动打开。
识别结果保存在当前浏览器会话中，文件名、大小或版本元数据变化后失效；加密包沿用密码输入流程。只识别外层格式，不自动解压嵌套包。

压缩包内的 JPG/JPEG、PNG、GIF、WebP、BMP 图片预览和下载不设 32 MiB 单文件上限；按索引声明大小读取并校验，ZIP 大图片使用最大 8 MiB 的读取窗口。
图片缓存仍按 30 张 / 256 MiB 淘汰（当前图片保留），原有读取超时、固实包和需要整包读取的特殊加密 RAR 限制仍适用。
