# 123 云盘工具箱

围绕 [123 云盘开放平台](https://123yunpan.yuque.com/org-wiki-123yunpan-muaork/cr6ced)（`open-api.123pan.com`）的三件套：

| 组成 | 位置 | 说明 |
| --- | --- | --- |
| **API 客户端库** | `api/` | 封装认证、限流重试、文件列表/搜索/详情、秒传与上传、WebDAV 直链、Redis 缓存 |
| **Web 文件浏览器** | `app.py` `routes/` `templates/` | Flask 应用，浏览、搜索、查看详情、取下载链接 |
| **批量上传脚本** | `upload_core.py` + 三个 CLI | 本地目录上传、清单秒传、批量秒传 |

## 快速开始

```bash
# 1. 安装依赖（需要 uv）
uv sync

# 2. 准备配置
cp config.json.template config.json
$EDITOR config.json          # 填入开放平台的 CLIENT_ID / CLIENT_SECRET

# 3. 启动 Web 浏览器
uv run python app.py         # http://localhost:8080
```

Redis 是可选依赖：连不上时会自动降级为不使用缓存，只是文件详情查询会多打几次接口。

## 配置说明（`config.json`）

| 键 | 必填 | 说明 |
| --- | --- | --- |
| `CLIENT_ID` / `CLIENT_SECRET` | 是 | 开放平台应用凭据 |
| `SECRET_KEY` | 否 | Flask session 密钥，不用 session 时无所谓 |
| `REDIS.ENABLED` | 否 | 为 `false` 或连不上时不使用缓存 |
| `REDIS.HOST` / `PORT` / `DB` / `PASSWORD` | 否 | Redis 连接参数；不写这一段则回退到 `localhost:6379`（命令行脚本和 Web 应用都按这里读） |
| `WEBDAV.ENABLED` | 否 | 是否启用 WebDAV 直链功能 |
| `WEBDAV.USERNAME` / `PASSWORD` | 启用时必填 | WebDAV 账号（早期模板里叫 `USER`，仍兼容） |
| `WEBDAV.BASE_URL` | 启用时必填 | 形如 `https://webdav-xxxx.pd1.123pan.cn`（早期模板里叫 `HOST`） |
| `WEBDAV.PATH_PREFIX` | 否 | URL 路径前缀，默认 `/webdav` |

`config.json` 已在 `.gitignore` 里，不要提交（也不要写进任何 md 文档里）。

## 命令行工具

三个脚本共用 `upload_core.py`，秒传口径完全一致。

### 上传本地目录

```bash
uv run python upload_folder.py /path/to/folder 远程/子目录
uv run python upload_folder.py /path/to/folder --dry-run     # 只打印计划
```

同名同大小文件跳过；每个文件先试 SHA1 秒传，未命中再走分片上传。

### 从清单秒传

清单支持两种格式：

- JSON：`{"commonPath": "远程/目录", "files": [{"path": "a/b.txt", "size": 123, "etag": "<md5或sha1>"}]}`
- 123 云盘导出文本：`etag#size#path$etag#size#path$...`

```bash
uv run python upload_from_json.py files.json
uv run python upload_from_json.py files.json -d 目标目录 -w 16 --rate 10
uv run python upload_from_json.py files.json --tree 目录树.txt
```

处理顺序（越靠前越省接口调用，也越不容易撞限流）：

1. **目录树预筛**（`--tree`）：传了目录树导出文件就先按文件名零请求地筛掉已上传的，连目标目录都不用列
2. **目标目录判重**：先列一次目标目录，云端已有同一文件就不发请求（也不会造出重复文件）
3. **并发秒传**：剩下的按 `--rate` 限速并发处理
4. **失败重试**：失败的串行重试一轮，仍失败才计入失败

判重只看云端现状（目录树导出 / 现列目录），不依赖任何本地"已完成"记录。

判重规则（默认"宽松"）：

- 清单里的哈希能解出 **MD5**，且与云端记录一致 → 确定是同一文件，跳过
- 清单只有 **SHA1**（没法直接比 MD5）→ 同目录 + 同名 + 同大小即跳过，日志会标注"未校验内容"；
  想每次都发请求校验用 `--verify`
- 同名同大小但 **MD5 不一致** → 不静默跳过、也不造重复文件，单独列为"内容冲突"等你确认

**目录树预筛（`--tree`）**：网页端对目标文件夹"导出目录树"得到 txt，传给 `--tree`，
判重就先按"这个位置有没有这个文件名"零请求地筛一遍——目录树里已有的直接跳过，
全部命中时一个请求都不发；目录树里没有的才解析目标目录、走秒传。两点注意：

- 导出的目录树**只有文件名**，校验不了大小和内容（同名不同版本的文件会被跳过）；
  要稳妥加 `--tree-verify`，让命中的条目再列目录按大小/MD5 核实
- 目录树是导出那一刻的快照，云端之后的变化它看不到——上传前现导出即可。
  重跑会按最新导出重新判

导出根默认按首行是"我的文件" = 网盘根来换算；别的对应关系用 `--tree-root` 指定。
目录树文件也可以是带大小/哈希的清单文本（`etag#size#path$...`），那种会自动按
大小 + MD5 的严格口径判重。


相关开关：

| 参数 | 作用 |
| --- | --- |
| `--rate N` | 每秒请求数上限，默认 8；`0` 表示不限速 |
| `--tree FILE` | 目录树导出文件，先按文件名零请求预筛已上传的文件 |
| `--tree-root PATH` | 目录树根对应的远程路径（默认：首行，"我的文件" 视为网盘根） |
| `--tree-verify` | 目录树名字命中后仍列目录核实大小/MD5（默认直接跳过） |
| `--no-dedup` | 不列目标目录做判重（目标目录特别大时可能更划算） |
| `--verify` | 清单只有 SHA1 时也发请求确认，而不是按同名同大小跳过 |
| `-v` / `--verbose` | 逐条打印每个文件的结果 |

**输出默认是紧凑的**：整个运行过程是一块两行的进度区（终端里原地刷新），第一行是当前阶段
（准备目录 / 判重 / 秒传 / 重试）和正在读取的目录，第二行是整体进度条。进度条的分母始终是
清单总条数，判重解决一条、秒传完成一条都算 +1，所以阶段切换时进度不会归零重来。按阶段推进
速率估的"剩 X"：判重/建目录阶段显示在第一行（那时进度条基本不动），秒传阶段显示在第二行
（和进度条同一个口径）。逐条明细只在 `-v` 时打印；失败项和"内容冲突"永远会逐条打印，
未命中的文件在汇总里最多列出 10 条（其余写 `-v` 查看）。

```
🔍 判重 1,203/5,000 · 12.3/s · 剩 05:12 · 📂 读取目录快照 /图片（第 2 页）
▶ 1,180/5,000 [██████░░░░░░░░░░] 24% · ✓ 1,157 ⏭ 23

⚡ 秒传 8 并发
▶ 3,300/5,000 [█████████████░░░░░] 66% · ✓ 2,100 ⚠ 12 ⏭ 1,188 · 6.4/s · 剩 04:21
```

输出被重定向到文件/管道时，同一个进度区退化成"换目录/换阶段时打印一行、长时间无变化按
5 秒补一次"，所以日志里也能看出进展。

### 批量秒传

```bash
uv run python batch_upload.py /path/to/manifest_dir -d 远程前缀目录 -w 16
```

每个清单都会处理，没有本地"已完成"记录可跳——判重靠 `--tree` 预筛或现列目标目录。目录树缓存和目录快照跨清单复用：同一棵目录树只建一次，同一个目录只列一次；`--tree` 所有清单共用一份。

每个清单处理完打一行明细（总数、已有多少、秒传多少）：

```
[3/8] 处理: 电影_346.5T.json
  ✅ 完成 (83.2s) 合计 123,456 条：已有 122,000（目录树 121,000，MD5 一致 1,000），秒传 1,450，未命中 5，失败 1
```

### 结果口径

| 结果 | 含义 |
| --- | --- |
| 已有 | 云端已有该文件而未发请求：目录树按名 / 列目录 MD5 一致 / 同名同大小（未校验内容） |
| 秒传 | 发了秒传请求并命中 |
| 未命中 | 接口**正常返回**，但云端没有可复用的文件（需要常规上传，本工具不做） |
| 失败 | 调用本身出错（网络/业务错误码），**不代表**云端没有这个文件 |
| 其他跳过 | 记录不完整（缺路径/哈希）、目录创建失败、内容冲突 |

> 秒传接口只有 `reuse=true` 算成功。异常和"未命中"必须分开统计，否则失败会被误报成"云端没有该文件"。

## 目录结构

```
api/                     客户端库（唯一公共入口是 api.client.Pan123Client）
  client.py              对外统一接口，委托给下面几个模块
  auth.py                token 获取/缓存（缓存固定在 ~/.cache/pan123_api/token.json）
  http_client.py         统一重试（5xx、业务码 1/429/20103）与可选限速
  ratelimit.py           令牌桶限速器
  file_service.py        文件列表/路径/上传/秒传/WebDAV
  cache.py               Redis 文件元数据缓存（JSON 序列化）
  models.py              File / FileList
  config.py              config.json 解析
routes/                  Flask 蓝图（main 页面 / api 接口）

tests/                   pytest 测试（不依赖网络/Redis/真实配置）
```

## 注意事项与已知限制

- **token 上限**：同一 `client_id` 最多同时存在 3 个 token（有效期 30 天）。token 缓存固定在 `~/.cache/pan123_api/token.json`（权限 0600），这样从不同目录运行也共用同一个 token，不会互相挤掉。
- **接口限流**：限流是**账号级**的。实测同时并发超过约 8 个请求，接口会返回 HTTP 200 + 业务码 1（"请慢一点"）；再加线程也不会更快，吞吐封顶约 8 请求/秒。所以秒传按速率节流而不是堆并发，业务码 1 会被自动退避重试。目录创建保持串行（mkdir 另有 20 QPS 限制）。
- **目录缓存**：`FileService` 的目录/目录ID缓存只在本进程内有效，重启后重建。
- **Web 端没有鉴权**：`app.py` 默认监听 `0.0.0.0`，同网段任何人都能浏览云盘。长期运行请放在带认证的反向代理后面，或设 `FLASK_HOST=127.0.0.1`。调试模式默认关闭，需要时用 `FLASK_DEBUG=1` 临时开启（Werkzeug 调试器可执行任意代码，不要对外暴露）。
- **WebDAV 直链含明文密码**：详情页展示的 WebDAV URL 里带着账号密码，只在本机使用，不要外发。日志里已做脱敏。
- **单文件限制**：分片上传路径按官方文档的单文件 10GB 设计，实际可用额度取决于账号权益包。
